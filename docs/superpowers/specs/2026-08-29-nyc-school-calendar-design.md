# NYC Public Schools 2026–27 Calendar — ICS + HTML Generator

Date: 2026-08-29
Status: Approved design (user-approved in session)

## Goal

Turn the official NYCPS 2026–27 school year calendar
(https://www.schools.nyc.gov/docs/default-source/sections/calendar/2026-27-school-year-calendar.pdf)
into:

1. `nyc-school-calendar-2026-27.ics` — one combined RFC 5545 calendar with every
   event from the PDF (35 PDF rows → 36 all-day events), importable into Google/Apple/Outlook.
2. `index.html` — static, dependency-free browsable view of the same data
   (month grids Sep 2026–Jun 2027, category badges, legend, category filter).

Both artifacts are generated by one stdlib-only Python script (`generate.py`),
so the data lives in one place and corrections/regeneration are one command.

## Deliverables

```
nyc-school-calendar/
├── generate.py                        # event data + ICS emitter + HTML writer
├── nyc-school-calendar-2026-27.ics    # generated
├── index.html                         # generated
└── docs/superpowers/specs/            # this spec
```

## Source data & integrity

- The PDF parses cleanly except page 2, where markit extraction flattened the
  Event column into one paragraph. Reconstruction is 1:1 and deterministic:
  21 date rows on page 2 ↔ 21 event strings (verified by splitting the
  flattened paragraph). Page 1 (14 rows) parsed normally. Total: 35 PDF rows →
  36 generated events (see Event modeling).
- Every event carries the PDF's stated weekday; `generate.py` asserts each
  date's real weekday matches it (catches any misaligned row at generation
  time). Spot checks: Sep 10 2026 = Thu (first day), Sep 21 = Mon (Yom Kippur),
  Jan 18 2027 = Mon (MLK), May 31 = Mon (Memorial Day), Jun 28 = Mon (last day).
- Before finalizing data, page 2 alignment is re-verified with a
  layout-preserving extraction (`pdftotext -layout` or equivalent).

## Event modeling

- One all-day event per PDF row. Ranges are single events spanning the range
  (Winter Recess = one event Dec 24–Jan 1; Regents = one event Jun 15–18 and a
  second Jun 21–25, matching the PDF's two segments).
- No invented clock times: the PDF only specifies "evening" / "afternoon and
  evening" for conferences, so those are all-day events with the PDF's note
  (e.g. "students in these schools dismissed three hours early") in
  DESCRIPTION.
- Four categories: `Schools Closed`, `Parent-Teacher Conferences`,
  `Regents`, `Key Dates` (first/last day, Election Day remote, PD Day,
  Spring Semester, Clerical Day, Anniversary Day).
- Multi-day "not in attendance" semantics stay in DESCRIPTION (e.g. Clerical
  Day applies only to listed grade bands), never encoded as fake multi-day
  closures.

## ICS details (RFC 5545)

- All events: `DTSTART;VALUE=DATE:YYYYMMDD`; ranges use exclusive `DTEND`
  (end = last day + 1 day) per RFC 5545 §3.6.1.
- Calendar: `X-WR-CALNAME:NYC Public Schools 2026–27`,
  `X-WR-TIMEZONE:America/New_York`, proper `PRODID`, `VERSION:2.0`,
  `CALSCALE:GREGORIAN`, `METHOD:PUBLISH`.
- Stable UIDs: `<slug-of-dates+summary>@nycps.harness` so re-import updates
  rather than duplicates.
- `DTSTAMP` = generation time (UTC). Text escaping per §3.3.11; lines folded
  at 75 octets per §3.1.
- No `VTIMEZONE` needed (all values are DATE, not DATE-TIME).

## HTML details

- Single file, inline CSS, no JavaScript frameworks; a ~30-line vanilla filter.
- Ten month grids Sep 2026–Jun 2027; each event day gets a colored badge keyed
  to its category; ranges shade their span of days.
- Header: title, link to the .ics download, source PDF link, legend.

## Generator structure

- `generate.py`, stdlib only (`datetime`, `dataclasses`, `html`, `textwrap`).
- `EVENTS`: list of dataclass rows (start, end, weekday, summary, category,
  description) — the spec table above, verbatim.
- `emit_ics(events) -> str`, `emit_html(events) -> str`, `main()` writes both
  files and runs all assertions.

## Verification

1. `python3 generate.py` runs clean; writes both artifacts.
2. Assertions inside the generator: event count == 36 (35 PDF rows; the
   two-segment Regents row emits two contiguous events); every event's weekday
   matches its date; category values within the four allowed; DTEND exclusive
   invariants.
3. ICS parse-back: strict checks — every VEVENT has UID/DTSTAMP/DTSTART
   VALUE=DATE; no line exceeds 75 octets after folding; CRLF line endings.
4. HTML: rendered in a real browser; month grids and badges visually confirmed.
5. Manual eyeball of the full event list above against the PDF (already done
   in design; repeated during implementation on the layout-preserved text).

## Non-goals

- No timed events (PDF has no clock times; per-school conferences vary anyway).
- No per-audience .ics splits (user chose one combined calendar).
- No automatic PDF scraping — the calendar is published once a year; data is
  reviewed data, not scraped data.
